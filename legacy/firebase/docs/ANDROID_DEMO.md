# Android 앱 시연과 검증

개발 범위는 작업자 Android 앱과 관리자 웹이다. 스마트워치 앱은 포함하지 않는다.

## iPhone만 있어도 PC에서 시연하기

작업자 앱의 소스·빌드·시연 안내는 별도 [safeloop-app- 저장소 README](https://github.com/jmwshye/safeloop-app-#readme)로 옮겼습니다. 이 웹 저장소의 `android/`는 제거했습니다.

iPhone에는 Android APK를 설치할 수 없습니다. PC의 Android Emulator 또는 팀원의 Android 실기기로 확인하세요. 새 앱은 `SafeLoop-Worker-0.2.apk`이며 이전 `SafeLoop-Android-demo.apk`와 구분합니다.

1. Android Studio에서 `safeloop-app-` 저장소 최상위 폴더를 엽니다. JDK 17 / SDK 35 / Gradle 8.9를 사용합니다.
2. 이 PC의 영문 경로 별칭은 `C:\Users\Public\Documents\ESTsoft\CreatorTemp\safeloop-worker-app`입니다.
3. 가상 기기를 실행하고 새 APK를 설치합니다. 처음에는 항상 체험 모드로 열립니다.
4. 오늘 화면에서 출근·작업 전 확인을 기록하고 앱을 다시 열어 저장 여부를 확인합니다.
5. 내 정보 → 앱 체험 도구에서 본인 확인 알림을 만들고 괜찮아요 응답과 15초 무응답을 각각 확인합니다.
6. 동료 현장 확인 체험에서 수락 → 현장 도착 → 사진 촬영 → 직접 안전 확인 → 제출을 진행합니다.

체험 기록·사진은 이 기기에 저장되며 앱을 다시 열어도 유지됩니다. 다른 사람에게 실제 푸시를 보내지 않습니다. 역할 전환 화면은 없습니다. 실제 센서 정확도와 잠금 화면 동작은 Android 실기기로 별도 검증합니다. 119 버튼은 전화 화면만 열며 시연 중 실제 긴급 전화를 걸지 않습니다.

## 실제 기기 간 연결 시험

`SETUP.md`에 따라 Firebase Authentication, Firestore, Storage, Functions, FCM, Cloud Tasks를 연결하고 배포해야 한다. 앱 저장소의 `app/google-services.json`과 웹의 `.env.local`은 같은 Firebase 프로젝트를 사용한다. 설정 파일·키를 저장소에 올리지 않는다.

추가 서버 함수는 `scheduleSelfCheck`, `scheduleVisitCheck`(Firestore 이벤트), `visitTimeout`, `viewCallPhoto`이다. 기존 함수와 함께 배포한다. Firestore 이벤트는 재시도를 켜고 DB에 저장된 응답 기한에 맞춰 Cloud Tasks를 예약한다. 배포 계정과 런타임 서비스 계정에 Eventarc/Firestore 트리거, Cloud Tasks 큐 생성·등록·호출 권한을 설정한다. Firebase 프로젝트의 요금제·리전·IAM 설정에 따라 별도 준비가 필요하다.

1. 관리자 웹에서 책임자 계정으로 현장을 만들고 참여 코드를 확인한다.
2. Google Play 이미지 에뮬레이터 **2대**에 각각 다른 작업자 계정으로 로그인한다. 두 작업자에게 같은 작업 구역을 입력하고 출근 기록을 저장한다.
3. 관리자 웹은 `.env.local`을 설정한 Firebase 연결 모드로 실행한다. 기본 공개 웹 시연 모드는 실제 앱의 기록과 동기화되지 않는다.
4. 감지 대상 앱의 debug 빌드에서 내 정보의 `개발용 서버 시험 신호`를 누른다. 이 버튼은 실제 서버 호출과 동료 알림을 발생시키므로 시험 계정·현장에서만 사용한다. release에는 표시되지 않는다.
5. 15초 무응답 후 다른 에뮬레이터에 수신되는 알림을 확인한다. 알림을 열고 수락, 도착, 주변 사진 촬영, 완료 제출을 진행한다.
6. 관리자 웹의 `작업자 안전 확인`에서 진행 상태와 확인 사진을 조회한다.
7. 사진 미첨부 완료 거부, 다른 동료의 완료 처리 거부, 본인 응답 기한 초과 거부, 수락 후 120초 사진 미완료 알림, 연결 끊김을 각각 확인한다.

주변 작업자는 현재 **같은 작업 구역**과 응답 가능 여부로 선정한다. GPS 거리·실내 층별 위치로 가까운 사람을 자동 추정하지 않는다. 같은 구역 작업자, 지정 동료, 책임자에게 요청한다. 30초 무응답이면 남아 있는 같은 구역 동료를 추가 호출하며, 추가 대상이 없으면 관리자 웹에 미완료 상태가 남는다. 푸시 발송 성공은 수신·열람·현장 확인 성공과 구분한다.

## 휴대폰 감지 원리와 실제 기기 검증

GPS 속도를 상시 측정하는 방식이 아니다. 선형가속도 센서로 급격한 움직임 변화를 감지한다. 선형가속도 센서가 없으면 가속도 센서에서 저역통과 필터로 중력을 근사 제거한다.

- 시험 규칙: 가속도 크기 29.43m/s² 이상 → 이후 7초 동안 저움직임 구간 비중 70% 이상 → 확인 요청. 1초 이상 센서 공백이면 후보를 폐기하며, 60초간 중복 감지를 억제한다.
- GPS 적분 속도나 실제 낙상 여부를 판정하지 않으며, 공구 사용·휴대폰 낙하와 신체 사고를 완전히 구분하지 못한다. 무충격 실신도 현재 규칙의 감지 대상이 아니다.
- 감시는 사용자가 시작하는 foreground service와 상시 알림으로 실행한다. 화면 꺼짐 중 CPU 정지를 줄이기 위해 감시 동안 partial wake lock을 사용하므로 배터리 사용량을 측정하고 휴식·퇴근 때 감시를 종료한다.
- 본인 알림은 서버 연결을 기다리지 않고 기기에서 먼저 표시한다. 서버 연결 실패·결과 불명 시 동료 호출 성공으로 표시하지 않는다. 통신이 끊긴 동안 다른 기기 알림을 보장할 수 없다.
- 앱 강제 종료·시스템에 의한 프로세스 종료 후 자동 감시 재시작은 보장하지 않는다. 센서·통신·알림 상태를 실기기에서 확인한다.

Android 실기기는 팀원 기기 또는 대여 기기를 사용한다. 앱 감시 시작 → 몸에 휴대 → 걷기·앉기·계단·작업 동작의 오탐을 기록한다. 기기를 떨어뜨리거나 사람이 낙상하는 방식으로 시험하지 않는다. 감지 입력은 합성 센서 데이터와 debug 시험 신호로 재현한다.

실기기 필수 시험: 잠금 화면·30분 이상 화면 꺼짐, 알림 권한 거부, 알림 채널 차단, 절전 모드, 감시 종료, 앱 강제 종료, 네트워크 단절·복구, 다른 계정 기기 간 FCM, 카메라 취소·재촬영, 119 전화 화면 접근. 센서 정확도와 배터리는 에뮬레이터 결과만으로 합격 판정하지 않는다.
